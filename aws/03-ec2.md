# EC2 (Elastic Compute Cloud)

Máquinas virtuales en AWS.

| Concepto | Qué es |
|---|---|
| **AMI** | Imagen del SO (Ubuntu, Amazon Linux, Windows…). El ID es **distinto en cada región**. |
| **Instance type** | CPU, RAM y red: `t2.micro`/`t3.micro` (free tier), familias `t` (burstable), `m` (general), `c` (CPU), `r` (RAM) |
| **EBS** | Disco (volumen de bloques): `gp3` (SSD general), `io2` (IOPS altas), `st1`, `sc1` (HDD) |
| **Key pair** | Llave SSH. AWS guarda la pública y tú la privada. |
| **Security group** | Firewall **stateful** a nivel de instancia. Por defecto bloquea todo el tráfico de entrada. |
| **User data** | Script que se ejecuta en el **primer arranque** (como root) |

## EC2 con Terraform

```hcl
resource "aws_key_pair" "web" {
  public_key = file("/root/.ssh/web.pub")       # generar con: ssh-keygen -t ed25519 -f ~/.ssh/web
}

resource "aws_security_group" "ssh-access" {
  name        = "ssh-access"
  description = "Allow SSH"
  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]                 # en real: limitar a tu IP
  }
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "webserver" {
  ami                    = "ami-0edab43b6fa892279"
  instance_type          = "t2.micro"
  key_name               = aws_key_pair.web.key_name
  vpc_security_group_ids = [aws_security_group.ssh-access.id]
  user_data              = <<-EOF
    #!/bin/bash
    apt update && apt install -y nginx
    systemctl enable --now nginx
  EOF
  tags = {
    Name = "webserver"
  }
}

output "publicip" {
  value = aws_instance.webserver.public_ip
}
```

```bash
terraform apply
ssh -i ~/.ssh/web ubuntu@$(terraform output -raw publicip)
```

- **Usuario SSH según la AMI**: `ubuntu` (Ubuntu), `ec2-user` (Amazon Linux), `admin` (Debian).
- **Cambiar `user_data`** no recrea la instancia (el script solo corre en el primer
  arranque), salvo que pongas `user_data_replace_on_change = true`.
- En lugar de fijar el ID de la AMI, se puede buscar con el data source `aws_ami`
  ([terraform/04](../terraform/04-comandos-lifecycle-data-sources.md)).
